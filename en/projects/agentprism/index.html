AgentPrism

Context economics for AI agents: a local tool that prices every piece of an agent’s context at cache rates.

Research

How it works
StatusResearch and a prototype. Twelve days of a multi-agent studio’s work analysed locally — no text left the machine. A real-time advisor already works (--watch mode): it shows what in the context is expensive and useless, and changes nothing by itself.
Next stepA link to memory.

Where it is going

  1. Next

    A link to memory: save what will still be needed before compacting — compaction gets cheaper and a long context stops being a necessity.

  2. Then

    Measure the cost of forgetting instead of assuming it in a simulation.

  3. Goal

    Check the findings on other users’ and teams’ data, and test every “it got better” so it survives the question “is this just luck?”.

A development plan, not a promise of dates.

What I found

A cache-rate ledger

A local tool prices every piece of an AI agent’s context at cache rates; Claude Code’s own accounting for the same tokens falls inside its price bounds for every model.

~85% is re-sending context

Over 12 days of a multi-agent studio’s work, ~85% of the cost (at API prices) is context being sent again. By a liberal rule, about a fifth of the prompt cost is context after its last use — an upper bound.

A compaction rule against the exact optimum

A ski-rental-style compaction rule was tested against the exact optimum: in a simulation on one user’s data it stays within 4–16% of the optimum when the cost of forgetting is known. A fixed threshold is up to 3× worse.

A placebo test instead of “before and after”

A placebo test showed that a naive before/after comparison on agent logs produces false effects an order of magnitude large. It was replaced with an adjusted estimate and a switchback schedule.

Negative results

Recorded just like the positive ones.

How it was checked

Agent logs are analysed locally: every piece of context is priced at cache rates and compared with Claude Code’s own accounting. The compaction rule is compared with the exact optimum in a simulation, and the effect of changes is measured with an adjusted estimate rather than a naive before/after.
