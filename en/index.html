How I check quality

Checking is the weak spot of most AI projects. So “done” is said not by the agent and not by me, but by the check.

  • Test before codeFirst a check that fails, then the code that passes it.
  • A reviewer with a clean contextA separate agent with no history of the work reads the whole diff and looks for what was missed.
  • Merge only on a green checkA script merges by reading the check result, not the command output.
  • Cost accountingI break agent spend down from the logs — AgentPrism: ≈85% of cost is re-sent history (based on 12 days of logs)4 Nov 2026
  • Agent permissions and human approvalEach role has its own list of actions; money, publishing, access and deletion only after a human says yes.

Where I slipped and how I caught it

On 6 Nov 2026 a script merged a pull request on a failed check: “grep && merge” looked at the output text, not the result. After the review, merging goes only through check-and-merge.sh, which reads the check status. The lesson: a mechanism instead of attention.

I write code together with Claude Code: the architecture, the task setting, the review, the tests and the responsibility for the result are mine.
