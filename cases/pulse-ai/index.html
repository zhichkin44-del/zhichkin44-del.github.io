Pulse AI

An AI agent management platform: tasks dispatched to machines, human approval, merge only on green tests

The task

A studio with several AI projects and several work laptops needs one console: see the state of every project, dispatch tasks to agents on machines and keep decisions with a human — without reading agent logs.

Architecture

Risky actions — money, publishing, access, deletion — go to a human as an approval card.

Decisions: why this way

  1. A core with no runtime dependencies

    Node.js and its standard library: a smaller attack surface and no breakage from third-party updates. Modules plug in through one registry.

  2. SQLite and an audit log

    One database file on the admin’s machine: every login, decision and agent action is recorded; a backup is a file copy.

  3. SSE instead of WebSocket

    Data flows only from the server to the screen; the browser reconnects on its own.

  4. Agents work through MCP

    Tasks, reports and questions are permissioned tools, not free text: an agent’s role limits what it can call.

  5. Every task ends in a pull request

    A script merges by the check result. An agent saying “done” means nothing until the check is green.

What broke and how I fixed it

A merge on a red check

What happened
On 6 Nov 2026 a script merged a pull request although the check had failed: “grep && merge” looked at the output text, not the check result.
The fix
I removed the cause with a mechanism rather than attention: merging now goes only through check-and-merge.sh, which reads the check status and refuses anything that is not green.
