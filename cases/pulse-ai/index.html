Задача

Студии из нескольких ИИ-проектов и нескольких рабочих ноутбуков нужен один пульт: видеть состояние проектов, раздавать задачи агентам на машины и держать решения у человека — без чтения журналов агентов.

Архитектура

Опасные действия — деньги, публикация, доступы, удаление — идут человеку карточкой на одобрение.

Решения: почему так

  1. Ядро без рантайм-зависимостей

    Node.js и стандартная библиотека: меньше поверхность атаки и поломок от чужих обновлений. Модули подключаются через один реестр.

  2. SQLite и журнал аудита

    Одна база файлом на машине администратора: каждый вход, решение и действие агента записаны, резервная копия — копия файла.

  3. SSE вместо WebSocket

    Данные идут только от сервера к экрану; переподключение браузер делает сам, без своей логики.

  4. Агенты работают через MCP

    Задачи, отчёты и вопросы — инструменты с правами, а не свободный текст: роль агента ограничивает, что он может вызвать.

  5. Результат задачи — pull request

    Слияние делает скрипт по итогу проверки. Слова агента «готово» ничего не значат, пока проверка не зелёная.

Интеграции и API

  • GitHub APIpull request, статусы проверок, слияние
  • MCPинструменты платформы для агентов и общий чат по всем проектам
  • Claude Codeагенты на рабочих машинах
  • Tailscaleдоступ к пульту с телефона без открытых портов
  • SSEживое состояние экрана

Что сломалось и как починил

Слияние при красной проверке

Что случилось
06.11.2026 скрипт слил pull request, хотя проверка упала: команда «grep && merge» смотрела на текст вывода, а не на итог проверки.
Как починил
Разобрал причину и убрал её механизмом, а не внимательностью: слияние теперь идёт только через check-and-merge.sh, который читает статус проверки и отказывается при любом не-зелёном итоге.
